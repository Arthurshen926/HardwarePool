## 自动重连公平调度

发现地址与已认证后保存的地址现在合并为每节点一个候选，优先尝试从未尝试或最久未尝试的节点。
修复原先固定优先发现列表首项、长超时后反复重试同一设备，导致缓存地址节点迟迟无法连接的问题。
同一节点仍优先使用发现地址，失败时才尝试其自己的缓存地址。
有效配对、用户手动断开、已有连接以及十秒重试间隔仍生效，不改变信任或授权。

三个定向调度测试及共享前端生产构建通过；未进行多设备物理回归。

随后已使用 `cargo build --offline -p capyio-desktop --bin capyio-desktop --features tauri/custom-protocol`
重建原路径 `target/debug/capyio-desktop.exe`，包含本记录的两项 UI 改动；没有启动用户窗口、安装 APK 或修改配对。
构建仍有既存摄像头未使用代码警告。上文“尚未打包”仅描述第一步完成时的状态。

## 需要处理的连接失败

自动连接遇到证书、DPAPI 或配对记录读取错误时，只暂停该节点在当前窗口的自动重试。
设置页保留节点名称、原因和处理建议，提供明确的“问题已处理，重新尝试”按钮。
网络超时、拒绝连接仍继续原有重试；其他节点不受影响。
手动认证连接成功会解除对应暂停。暂停不持久化、不修改配对、不自动更新证书。
错误分类使用现有后端错误文字；未来后端稳定错误码可替换它。

连接问题卡片增加“检查此设备的地址与配对”，选择对应设备并聚焦地址框；不会自动重配对。
切换/重新选择设备地址时清除旧连接与凭据检查提示。异步凭据检查返回时核对当前选择，
避免 A 设备的“凭据可读取”误显示在 B 设备下。共享前端类型检查和构建通过；实际焦点交互尚待窗口验证。
